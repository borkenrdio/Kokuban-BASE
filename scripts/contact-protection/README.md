# 受信側への適用が必要

このフォルダは適用用の補助コードです。GitHub Pagesへの公開だけではGoogle Apps Scriptに反映されません。

現在稼働しているApps Scriptの既存コードを保存したうえで、validation.gsを追加し、doPost(e)の最初（メール送信・シート保存より前）で次の判定を呼び出してください。

```js
if (!validateCustomerInquiry_(e)) {
  return ContentService.createTextOutput('rejected');
}
```

既存の送信先、メール本文、保存処理は維持してください。新しいバージョンで既存のウェブアプリのデプロイを更新します。新URLを発行する場合はサイト側のdata-google-script-urlも更新が必要です。

上記は入力条件の検証です。チェック欄や時刻は送信者が偽装でき、営業目的の判定や高度なbot防止にはなりません。本格的な自動送信対策にはTurnstile等のトークンをサーバー側で検証し、検証失敗時にはメールを送らないようにします。必要なサイトキー・シークレットキーは未設定です。シークレットはApps Scriptのスクリプトプロパティに保存し、GitHubやHTMLには置かないでください。

現在のフォームはno-cors送信のため、ブラウザーから受信側の受付可否を読み取れません。受付確認まで行うには応答を読める送信基盤への変更が必要です。

適用後は、日本語の短い購入相談が届くこと、英語のみ・空欄・上限超過・honeypot入力・同意なし・不正な種別が通知されないことを確認します。営業の受信拒否ルールは、実際の迷惑メールの文面と正当な問い合わせの例を見て別途調整します。
