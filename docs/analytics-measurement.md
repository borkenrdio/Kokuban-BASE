## GA4での見方

1. **レポート → エンゲージメント → イベント**：check_start / check_complete / contact_viewを選び、イベント数と総ユーザー数を比較。
2. **探索 → 経路データ探索**：ノードを「ページパスとスクリーンクラス」にし、開始点をランディングページ、または終了点を/contact/に設定。途中のページを展開すると、問い合わせまでの実際の閲覧経路を確認できる。
3. **探索 → 自由形式**：行に「診断の推奨ブランド」、指標にイベント数・総ユーザー数、フィルタをイベント名check_completeとする。推奨インチや教室規模でも同様に集計できる。
4. **探索 → ファネルデータ探索**：check_view → check_start → check_complete → contact_viewの間接ステップ（途中に別ページがあっても可）を使い、診断から問い合わせ画面までの到達を確認。全訪問者の問い合わせ到達は診断経由に限定しない別ファネルにする。
5. 流入別に見る場合はセッション単位で「セッションの参照元 / メディア」等を使う。全体を見る場合は流入元フィルタを付けない。

カスタム定義は登録後のデータから利用でき、通常レポートには24〜48時間程度かかる場合がある。過去の未計測の診断開始やページ移動クリックは遡って復元できない。既存page_viewの閲覧経路は取得済み期間から確認できる。

問い合わせ画面への到達や診断完了は、相談そのものとは別の補助指標なので、新たに広告の入札用キーイベントにはしていない。キーイベントや広告設定は変更しない。

## 実装上の約束

- ページビューは既存Googleタグに任せ、独自page_viewを重複送信しない。
- 共通assets/analytics.jsを全GAタグ設置ページと生成テンプレートで読み込む。
- 名前・メール・電話・相談本文・リンクのクエリやハッシュは独自イベントへ送信しない。診断は選択肢の自由記述を持たず、結果のブランド・サイズ・教室規模コードのみ。
- 内部リンクのクリックは移動元・移動先のパスのみ。外部の移動先やブラウザーを閉じた後の行動は追跡しない。
- GAを拒否する設定、広告ブロッカー、ブラウザー制限などで計測されない利用がある。GA4のユーザー数は実在する人数の厳密な値ではない。
